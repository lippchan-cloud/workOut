## Why

C 端「我的」只能改资料、改密、退出，用户看不到自己生成过的分享报告；顶栏也不展示登录态。账号目前只有用户名密码，无法绑定邮箱，也无法用邮箱验证码登录。账号相关操作除注销外缺少二次确认，容易误触。

## What Changes

- 「我的」二级选项增加 **报告记录**，进入三级列表 `/profile/reports`，展示当前用户已创建的分享报告并打开公开 `/report/{id}`。
- C 端顶栏右上角展示当前账号（用户名）；未登录显示「登录」，点击进入登录页并带上当前路径作为 redirect。
- 账号安全支持 **绑定邮箱 / 解绑邮箱**；验证码为 **4 位数字**。绑定成功后可用 **邮箱 + 验证码** 登录；原用户名密码登录保留。
- 「我的」里与账号相关的操作（退出登录、修改密码、绑定/解绑邮箱、注销账号）均须二次确认弹窗，取消则不提交。

## Capabilities

### New Capabilities

- `user-auth`: 当前会话查询、邮箱绑定/解绑、4 位数字验证码、邮箱验证码登录；用户名密码登录仍可用。

### Modified Capabilities

- `user-profile`: 「我的」选项增加报告记录；账号安全含邮箱；账号操作须二次确认。
- `share-report`: 登录用户可列出本人已有分享（不代他人、不新造快照）。
- `ui-hierarchy`: 顶栏右上角登录态；「我的」二级选项含报告记录。

## Impact

- 前端：`AppShell` 顶栏账号；`AuthContext` 持久化用户名；登录页增加邮箱验证码通道；`ProfilePage` 增加报告记录与确认弹窗；Vitest。
- 后端：Flyway 用户邮箱与验证码表；`GET /api/v1/auth/me`、发码/绑定/解绑/邮箱登录；`GET /api/v1/shareReports`；Security 放行发码与邮箱登录；Java 改动遵守 java-architecture-master。
- 发信：可配置 SMTP；未配置时本地记录验证码以便开发（生产应配置 SMTP）。不引入 OAuth / 短信 / 找回密码。
- 文档：产品/功能「本期不做邮箱」需改为已支持绑定与邮箱验证码登录。
