## 0. 三分钟读懂

**一句话定位：**

> workOut 是个人每日训练与饮食记账工具：用户注册登录后，用最短路径记下「今天消耗了什么、摄入了什么」，再按周回看，必要时按日导出；数据按账号隔离。

**核心承诺：**

1. 先认人：未登录可看到底部导航壳子；点 Tab 或点保存 / 导出等操作时，跳转登录 / 注册。
2. 当天就能记：登录后进入记录页，消耗 / 摄入各一条输入，日期默认当前时间。
3. 按周能看：日历默认选中今天；周切换是小控件，日期格子才是主体；有记录的日子右上角显示条数；点某一条进详情。
4. 一眼能分：消耗绿色、摄入红色。
5. 按日能带走：选中日期后可「导出」（实际 xlsx 双工作表：事项列表 + 成长曲线）；须先填身高和体重。文件含当时有效的身高、体重（按事项时间对齐历史）。
6. 人是自己的：「我的」先出现三个选项，再进身体资料或账号安全；身体资料可填真实日期；改资料会留下变更历史。
7. 能看变化：成长曲线在「我的」身体资料页下方（单位 cm/kg、时间轴、可拖、放大改时间粒度）。
8. 能分享：日历「分享」生成 H5 链接（`/report/:id`），公开只读报告含范围、用户名称、事项、曲线，并预留建议分析。

**本版本不做：** 卡路里自动计算、运动库、社交、组织/团队权限、邮箱验证与找回密码、营养分析报告。

## 1. 背景与问题

### 1.1 要解决什么

健身或控制饮食的人，最常卡住的不是「没有专业设备」，而是：

- 当天训练和进食随手记不下来，事后回忆不准。
- 消耗和摄入混在一起，回看时分不清。
- 需要把某一天的记录交给教练、营养师或自己做表时，没有现成导出。
- 多人共用同一设备或浏览器时，需要各自账号、数据互不可见。

### 1.2 产品判断

第一版做「账号登录 → 记下来、按天看、按天导出、补全身高体重」。  
不先做智能分析：先保证记录成本极低、回看路径清楚、数据跟人走。

### 1.3 成功标准（MVP）

| 场景 | 成功长什么样 |
| --- | --- |
| 登录注册 | 用户能注册账号并登录；未登录操作会跳到登录 / 注册页 |
| 当日记账 | 登录后 30 秒内完成一条消耗或摄入记录 |
| 回看 | 用户打开日历即可看到本周，默认落在今天，点某一天能看到**本人**当天全部记录 |
| 辨识 | 列表中消耗为绿色、摄入为红色，无需二次思考 |
| 带走 | 用户能按当前筛选导出一份 xlsx（须已填身高体重；含当时身体资料 + 成长曲线工作表） |
| 资料 | 用户能保存身高、体重与资料真实日期；变更有历史（按账号隔离） |
| 曲线 | 在身体资料页下方看身高(cm)/体重(kg)随时间，可拖动与改时间粒度 |
| 分享 | 生成可配置基址的 H5 报告链接，未登录可打开该范围快照 |
| 隔离 | 用户 A 看不到用户 B 的记录与资料 |

## 2. 目标用户

| 用户 | 典型诉求 | 产品给什么 |
| --- | --- | --- |
| 个人训练者 | 记下今天练了什么、吃了什么 | 账号 + 记录页 + 按周日历 |
| 需要复盘的人 | 按天对照消耗与摄入 | 按时间正序列表、颜色区分 |
| 需要外发记录的人 | 把某天数据交给教练或自己归档 | 按筛选导出 xlsx / 分享 H5 |

MVP 按**多账号、个人数据隔离**设计：一人一账号，不引入组织、角色、协作。

## 3. 产品定位

### 3.1 是什么 / 不是什么

| 是 | 不是 |
| --- | --- |
| 带登录的每日消耗 / 摄入轻量记账本 | 不是健身社交社区 |
| 按周查看的个人日历账本 | 不是专业营养分析软件 |
| 可按日导出的个人数据工具 | 不是企业级多租户 SaaS / 组织权限系统 |

### 3.2 信息架构

底部三个一级入口 + 各 Tab 的二级选择 / 三级表单或详情；独立登录 / 注册页。

| 层级 | 记录 | 日历 | 我的 |
| --- | --- | --- | --- |
| 一级 | 底部 Tab | 底部 Tab | 底部 Tab |
| 二级 | 大按钮后的消耗/摄入选择 | 周条（小周切换）；导出 / 分享 | `/profile` 三选项：身体资料、账号安全、退出登录 |
| 三级 | 消耗/摄入表单 | 事项详情 `/calendar/records/:id`；补记进入记录二级 | 身体资料 `/profile/body`（表单 + 成长曲线）；账号安全 `/profile/account`（改密/注销；ADMIN 见 CMS） |

| 导航 / 页面 | 名称 | 用户任务 |
| --- | --- | --- |
| 第一项 | 记录 | 写下当日消耗项、当日摄入项（需登录） |
| 第二项 | 日历 | 按周/月看列表（含时分），点条目进详情，导出 / 分享（须身高体重，需登录） |
| 第三项 | 我的 | 先选再填：身体资料（含真实日期与成长曲线）或账号安全（需登录） |
| 独立页 | 登录 / 注册 / 公开报告 | 用户名 + 密码；成功后回到原目标页。报告 `/report/:id` 不走三 Tab |

默认落地：「记录」Tab 壳子（可见导航）。未登录时点 Tab 或业务操作 → 跳转登录。

### 3.3 产品原则

1. **先鉴权再记账**：业务数据必须归属当前登录用户。
2. **点进再跳**：未登录可看导航壳；点 Tab 或保存 / 导出等操作时跳转登录 / 注册。
3. **默认今天**：记录日期默认操作时间；日历默认选中今日。
4. **一条一事**：消耗、摄入各自独立输入，互不混写。
5. **颜色即语义**：消耗绿、摄入红，全产品一致。
6. **先记后算**：本版只存用户写下的内容，不做热量公式。
7. **启动要简单**：前后端不分离，用户用 CLI 一条命令拉起。

## 4. 用户路径

### 4.0 登录 / 注册

1. 打开应用，看到底部导航与「记录」壳子。
2. 点击任一 Tab，或点击保存 / 导出 / 保存资料等操作。
3. 跳转到登录页；可切换到注册页。
4. 注册：用户名 + 密码 → 成功后自动登录或引导登录。
5. 登录成功：带回 JWT，跳转到原先要点进的目标页（`redirect`）。

### 4.1 当天记账（已登录）

1. 进入「记录」。
2. 在消耗输入框写下内容（如「跑步 30 分钟」），保存。
3. 在摄入输入框写下内容（如「鸡胸肉一份」），保存。
4. 若不记账今天，可改记录日期后再保存。

### 4.2 按周回看（已登录）

1. 进入「日历」，看到本周，今日高亮选中；上一周 / 下一周是小字控件。
2. 鼠标划过或键盘聚焦日期格子有反馈；有记录的格子右上角显示当天条数。
3. 点某一天，下方列出该日**本人**全部记录，时间从早到晚，每条能看到时分；按月列表同样带日期+时分。
4. 点某一条进入只读详情，再编辑或删除；浏览器返回回到该日。
5. 绿色是消耗，红色是摄入。需要外发时点「导出」或「分享」（须先填身高体重）。「补记」是次要动作。
6. 成长曲线不在日历主路径；到「我的 → 身体资料」页下方查看。

### 4.3 完善个人资料（已登录）

1. 进入「我的」，先看到三个选项。
2. 点「身体资料」填写身高、体重、资料真实日期（默认此刻）并保存（有效变更写入历史，时间为所选日期）；页下方是成长曲线。
3. 点「账号安全」改密或注销；管理员在此进入 CMS。
4. 「退出登录」在选项层即可完成。返回键回到选项层。

## 5. 产品范围

### 5.1 本期必做（P0）

- 登录页、注册页：用户名 + 密码；JWT 鉴权。
- 未登录：可见导航壳；点 Tab 或业务操作跳转登录 / 注册；登录后回到目标页。
- 记录 / 日历 / 我的 / 导出：全部按当前用户隔离。
- 记录页：当日消耗项、当日摄入项各一个输入框；日期默认为操作时间，可改。
- 日历页：按周展示，默认选中今日；选中日后展示当天列表（含时分）；格子 hover/气泡；点条目进详情；可导出 / 分享。
- 列表：按记录时间正序；消耗绿色、摄入红色；月/日列表均展示记录时分。
- 按当前筛选导出 xlsx（事项列表 + 成长曲线两工作表；列含昵称、身高 cm、体重 kg，按事项 `recordedAt` 对齐历史快照）。缺身高或体重则拦截并引导资料页。
- 分享生成随机 token 的 H5：`{WORKOUT_PUBLIC_BASE_URL}/report/{id}`，公开报告展示范围 + 用户名称 + 事项 + 曲线 + 建议分析空态。
- 身体资料含真实日期；变更写入历史；注销时批量删除历史与分享。
- 成长曲线在 `/profile/body` 下方：单位 cm/kg、时间轴、横向拖动、放大缩小改 hour/day/week/month 粒度。
- 我的：二级三选项后再进身体资料或账号安全。
- CLI 启动整站（Spring Boot 托管前端静态资源 + API）。

### 5.2 明确不做（本期）

- 邮箱验证、短信验证、找回密码、第三方登录（微信等）
- 组织 / 团队 / 角色权限、账号互相可见
- 卡路里、宏量营养素自动计算
- 运动动作库、食物库、扫码识别
- 训练计划、打卡提醒、成就体系
- BMI 诊断结论或医疗建议（可存身高体重与变化曲线，不做健康建议）
- 分享到微信/微博等社交平台（本期仅站内 H5 只读链接）

### 5.3 可后续迭代（P1，不阻塞本期）

- 退出登录入口优化、改密
- 记录的编辑与删除（本期只新增，不改、不删）
- 按周 / 按月批量导出
- 基于身高体重展示 BMI 数值（仅展示，不做医疗建议）

## 6. 体验要求

| 维度 | 要求 |
| --- | --- |
| 未登录 | 可见导航壳；点 Tab / 业务操作跳转登录，不静默写数据 |
| 登录后 | 可直接完成记账闭环，不先走引导长页 |
| 日期 | 记录默认「现在」；日历默认「今天」 |
| 辨识 | 消耗 / 摄入颜色全局统一 |
| 层级 | 一级 Tab、二级选择、三级表单/详情；返回回到本 Tab 二级 |
| 按钮 | 主 CTA / 次要 / 文字小按钮分档；周切换不得做成大主按钮 |
| 日历格子 | hover 与键盘 focus；有记录显示数量气泡 |
| 空态 | 某日无记录时明确提示「这一天还没有记录」，而不是空白页 |
| 导出 | 无记录时提示无法导出或导出空表（见功能文档） |
| 启动 | 文档化一条 CLI 命令即可本地运行 |

## 8. 验收口径（产品）

满足以下即可认为 MVP 产品目标达成：

1. 未登录可见导航；点 Tab 或业务操作会进入登录 / 注册。
2. 能注册、能登录；登录后进入目标页。
3. 三个导航职责与本文第 3.2 节一致。
4. 能新增消耗记录、摄入记录，日期默认可改。
5. 日历按周展示且默认今天；切换日期后列表随之变化。
6. 列表时间正序，颜色语义正确。
7. 能按当前筛选导出 xlsx（事项列表 + 成长曲线），Excel 可打开；缺身高体重会引导补全。
8. 能保存并回显身高、体重与资料真实日期；身体资料页下方可见成长曲线。
9. 能分享 H5 报告链接（`/report/:id`），未登录可打开该范围快照。
10. 用户 A 的记录与资料对用户 B 不可见。
11. 通过 CLI 启动后，浏览器可完成本页全部操作。

功能规则、字段、异常与接口级说明见《功能文档》；架构与流程见《技术架构》。
