## 0. 三分钟读懂

**一句话定位：**

> workOut 是个人每日训练与饮食记账工具：用户用最短路径记下「今天消耗了什么、摄入了什么」，再按周回看，必要时按日导出。

**核心承诺：**

1. 当天就能记：打开即到记录页，消耗 / 摄入各一条输入，日期默认当前时间。
2. 按周能看：日历默认选中今天，选中某日后按时间正序列出当天记录。
3. 一眼能分：消耗绿色、摄入红色。
4. 按日能带走：选中日期后可导出 CSV。
5. 人是自己的：我的信息页可填写身高、体重等基本资料。

**本版本不做：** 卡路里自动计算、运动库、社交、多账号体系、营养分析报告。

## 1. 背景与问题

### 1.1 要解决什么

健身或控制饮食的人，最常卡住的不是「没有专业设备」，而是：

- 当天训练和进食随手记不下来，事后回忆不准。
- 消耗和摄入混在一起，回看时分不清。
- 需要把某一天的记录交给教练、营养师或自己做表时，没有现成导出。

### 1.2 产品判断

第一版只做「记下来、按天看、按天导出、补全身高体重」。  
不先做智能分析：先保证记录成本极低、回看路径清楚。

### 1.3 成功标准（MVP）

| 场景 | 成功长什么样 |
| --- | --- |
| 当日记账 | 用户 30 秒内完成一条消耗或摄入记录 |
| 回看 | 用户打开日历即可看到本周，默认落在今天，点某一天能看到当天全部记录 |
| 辨识 | 列表中消耗为绿色、摄入为红色，无需二次思考 |
| 带走 | 用户能按当前选中日期导出一份 CSV |
| 资料 | 用户能保存身高、体重等基本信息 |

## 2. 目标用户

| 用户 | 典型诉求 | 产品给什么 |
| --- | --- | --- |
| 个人训练者 | 记下今天练了什么、吃了什么 | 记录页 + 按周日历 |
| 需要复盘的人 | 按天对照消耗与摄入 | 按时间正序列表、颜色区分 |
| 需要外发记录的人 | 把某天数据交给教练或自己归档 | 按日 CSV 导出 |

MVP 按**单人本地使用**设计：一人一份数据，不引入登录、组织、权限。

## 3. 产品定位

### 3.1 是什么 / 不是什么

| 是 | 不是 |
| --- | --- |
| 每日消耗 / 摄入的轻量记账本 | 不是健身社交社区 |
| 按周查看的个人日历账本 | 不是专业营养分析软件 |
| 可按日导出的个人数据工具 | 不是多用户 SaaS |

### 3.2 信息架构（三个入口）

底部（或主导航）三个入口，对应 README 的三类能力：

| 导航 | 名称（建议） | 用户任务 |
| --- | --- | --- |
| 第一项 | 记录 | 写下当日消耗项、当日摄入项 |
| 第二项 | 日历 | 按周选日期，看当天列表，按日导出 CSV |
| 第三项 | 我的 | 填写身高、体重等个人基本信息 |

默认进入「记录」。

### 3.3 产品原则

1. **默认今天**：记录日期默认操作时间；日历默认选中今日。
2. **一条一事**：消耗、摄入各自独立输入，互不混写。
3. **颜色即语义**：消耗绿、摄入红，全产品一致。
4. **先记后算**：本版只存用户写下的内容，不做热量公式。
5. **启动要简单**：前后端不分离，用户用 CLI 一条命令拉起。

## 4. 用户路径

### 4.1 当天记账

1. 打开应用，落在「记录」。
2. 在消耗输入框写下内容（如「跑步 30 分钟」），保存。
3. 在摄入输入框写下内容（如「鸡胸肉一份」），保存。
4. 若不记账今天，可改记录日期后再保存。

### 4.2 按周回看

1. 进入「日历」，看到本周，今日高亮选中。
2. 点某一天，下方列出该日全部记录，时间从早到晚。
3. 绿色行是消耗，红色行是摄入。
4. 需要外发时，导出该日 CSV。

### 4.3 完善个人资料

1. 进入「我的」。
2. 填写身高、体重等基本信息并保存。
3. 之后打开仍能看到已保存内容。

## 5. 产品范围

### 5.1 本期必做（P0）

- 记录页：当日消耗项、当日摄入项各一个输入框；日期默认为操作时间，可改。
- 日历页：按周展示，默认选中今日；选中日后展示当天列表。
- 列表：按记录时间正序；消耗绿色、摄入红色。
- 按选中日期导出 CSV。
- 我的信息：身高、体重及必要基本信息的填写与保存。
- CLI 启动整站（Spring Boot 托管前端静态资源 + API）。

### 5.2 明确不做（本期）

- 登录 / 注册 / 多用户
- 卡路里、宏量营养素自动计算
- 运动动作库、食物库、扫码识别
- 训练计划、打卡提醒、成就体系
- 图表趋势、BMI 诊断结论（可存身高体重，不做健康建议）
- 分享到社交平台

### 5.3 可后续迭代（P1，不阻塞本期）

- 记录的编辑与删除（本期只新增，不改、不删）
- 按周 / 按月批量导出
- 基于身高体重展示 BMI 数值（仅展示，不做医疗建议）

## 6. 体验要求

| 维度 | 要求 |
| --- | --- |
| 首屏 | 启动后直接可记，不先走引导长页 |
| 日期 | 记录默认「现在」；日历默认「今天」 |
| 辨识 | 消耗 / 摄入颜色全局统一 |
| 空态 | 某日无记录时明确提示「这一天还没有记录」，而不是空白页 |
| 导出 | 无记录时提示无法导出或导出空表（见功能文档） |
| 启动 | 文档化一条 CLI 命令即可本地运行 |

## 8. 验收口径（产品）

满足以下即可认为 MVP 产品目标达成：

1. 三个导航均可进入，且职责与本文第 3.2 节一致。
2. 能新增消耗记录、摄入记录，日期默认可改。
3. 日历按周展示且默认今天；切换日期后列表随之变化。
4. 列表时间正序，颜色语义正确。
5. 能按当前选中日期导出 CSV，用表格软件打开可读。
6. 能保存并回显身高、体重。
7. 通过 CLI 启动后，浏览器可完成本页全部操作。

功能规则、字段、异常与接口级说明见《功能文档》。
