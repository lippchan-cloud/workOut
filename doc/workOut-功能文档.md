## 2. 信息架构与页面

### 2.1 导航与鉴权页

| 顺序 | 名称 | 路由建议 | 说明 |
| --- | --- | --- | --- |
| — | 登录 | `/login` | 用户名 + 密码；成功后按 `redirect` 回跳 |
| — | 注册 | `/register` | 用户名 + 密码；成功后登录或引导登录 |
| 1 | 记录 | `/` 或 `/record` | 一级大按钮 → 二级选类型 → 三级表单；需登录 |
| 2 | 日历 | `/calendar` | 周视图（小周切换 + hover + 气泡）+ 日/月列表（含时分）+ 导出 / 分享；需登录 |
| 2a | 事项详情 | `/calendar/records/:id` | 只读详情 + 编辑/删除；刷新走 GET by id |
| 2b | （兼容） | `/calendar/trends` | 重定向到 `/profile/body`，日历主路径不再放曲线 |
| 3 | 我的 | `/profile` | 二级三选项；需登录 |
| 3a | 身体资料 | `/profile/body` | 昵称/身高/体重/资料真实日期 + 下方成长曲线 |
| — | 公开报告 | `/report/:id` | 独立页（无三 Tab）：用户名称、事项列表、成长曲线、建议分析空态 |
| 3b | 账号安全 | `/profile/account` | 改密/注销；ADMIN 可见 CMS |

切换 Tab 不丢未提交表单时，需提示或自动保留输入草稿（建议：离开记录页前提示未保存内容）。  
未登录状态下点 Tab：不进入业务页内容加载，直接跳转 `/login?redirect=<目标路径>`。

### 2.2 页面结构（已登录）

```
┌─────────────────────────────┐
│          页面内容            │
│  记录 / 日历 / 我的          │
├─────────────────────────────┤
│  [记录]  [日历]  [我的]      │  ← 一级主导航
└─────────────────────────────┘
```

信息层级：一级 Tab → 二级选择层 → 三级表单或详情。浏览器从三级返回到该 Tab 的二级。

### 2.3 未登录壳子

```
┌─────────────────────────────┐
│     Tab 壳 / 空内容区        │
│  （可不请求业务数据）         │
├─────────────────────────────┤
│  [记录]  [日历]  [我的]      │  ← 可见；点击 → 登录
└─────────────────────────────┘
```

## 3. 登录 / 注册模块

### 3.1 注册

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 用户名 | 字符串 | 是 | 去首尾空格后 3～32 字符；字母数字下划线；全站唯一 |
| 密码 | 字符串 | 是 | 6～64 字符；前端不明文回显；后端哈希存储 |

交互：

1. 填写用户名、密码 → 点「注册」。
2. 成功：写入用户；可直接返回 JWT 并进入目标页，或提示「注册成功」并跳转登录（二选一，推荐直接发 Token）。
3. 失败：保留输入（密码可清空），展示中文错误。

| 条件 | 提示 |
| --- | --- |
| 用户名为空 / 非法 | 请填写合法用户名 |
| 用户名已存在 | 该用户名已被注册 |
| 密码过短 / 过长 | 密码长度需为 6～64 位 |
| 成功 | 注册成功 |

本期不做：邮箱、手机号、验证码、找回密码。

### 3.2 登录

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 用户名 | 字符串 | 是 | 已注册用户名 |
| 密码 | 字符串 | 是 | 与注册时一致 |

交互：

1. 填写 → 点「登录」。
2. 成功：前端保存 JWT（建议 `localStorage`）；跳转 `redirect`（无则进记录页）。
3. 失败：提示「用户名或密码错误」（不区分哪种，降低枚举风险）。

登录页提供「去注册」；注册页提供「去登录」。

### 3.3 前端鉴权守卫

| 触发点 | 未登录行为 |
| --- | --- |
| 点击底部任一 Tab | 跳转 `/login?redirect=<该 Tab 路径>` |
| 点击保存消耗 / 保存摄入 | 同上（redirect 指向记录页） |
| 点击导出 / 分享 | redirect 指向日历页 |
| 点击保存资料 / 进入我的拉资料 | redirect 指向我的页 |
| 业务 API 返回 401 | 清除本地 Token，跳转登录页 |

已登录：请求头携带 `Authorization: Bearer <token>`。

### 3.4 登出（最小）

「我的」页提供「退出登录」：清除本地 Token，回到记录壳（未登录态）。本期可不做服务端 Token 黑名单。

## 4. 记录模块

### 4.1 页面组成

记录页包含两块，互不影响：

| 区块 | 作用 |
| --- | --- |
| 当日消耗项 | 记录一次消耗（训练、运动等） |
| 当日摄入项 | 记录一次摄入（饮食等） |

每一块包含：

- 内容输入框（单行或多行文本）
- 记录日期时间控件
- 保存按钮

### 4.2 字段

#### 消耗 / 摄入记录（同结构，类型不同）

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 内容 | 字符串 | 是 | 去首尾空格后长度 1～500；空内容不可保存 |
| 记录时间 | 日期时间 | 是 | 默认 = 用户点击保存时的本地时间；用户可改 |
| 类型 | 枚举 | 系统填 | `CONSUME`（消耗）/ `INTAKE`（摄入） |
| 所属用户 | userId | 系统填 | 取自 JWT，前端不可伪造覆盖 |

数据层按「当前用户可拥有多条历史记录」存储。

### 4.3 日期默认与修改

| 行为 | 规则 |
| --- | --- |
| 进入页面 | 消耗、摄入两个日期控件均显示当前本地时间 |
| 用户未改日期 | 保存时以服务端收到请求时刻或前端提交的当前时间写入（两者需在功能上等价：即「操作时间」） |
| 用户修改日期 | 以用户选择的日期时间为准，可记到过去或未来日期 |
| 仅改日期、不改内容 | 内容仍必填 |

建议精度：精确到分钟。秒可由系统补 00。

### 4.4 交互

1. 用户填写消耗内容（可选改时间）→ 点「保存消耗」→ 成功提示 → 清空该块内容，日期重置为当前时间。
2. 用户填写摄入内容（可选改时间）→ 点「保存摄入」→ 同上。
3. 保存失败：保留已填内容，展示错误信息。
4. 保存成功不自动跳转日历；用户可继续记另一条。

### 4.5 校验与提示

| 条件 | 提示（可直接展示） |
| --- | --- |
| 内容为空 | 请填写内容 |
| 内容超过 500 字 | 内容不能超过 500 字 |
| 时间为空 / 非法 | 请选择有效的记录时间 |
| 保存成功 | 已记录 |
| 未登录 / 401 | 跳转登录 |
| 服务异常 | 保存失败，请稍后重试 |

## 5. 日历模块

### 5.1 周视图

| 项 | 规则 |
| --- | --- |
| 展示粒度 | 按周，一次显示 7 天 |
| 周起始 | 周一为一周第一天（国内习惯） |
| 默认选中 | 进入页面时选中「今天」 |
| 默认所在周 | 包含今天的那一周 |
| 切周 | 上一周 / 下一周为**小字控件**（`week-nav-btn`），不是大主按钮 |
| 格子主体 | 日期格子大于周切换；支持 `:hover` 与键盘 `:focus-visible` |
| 数量气泡 | 当天条数 > 0 时格子右上角显示数字；日模式一次请求 `from=周一&to=周日` 后前端聚合，禁止按日 N+1 |
| 今日标识 | 今天在周条上有「今」或高亮，与选中态可同时存在 |

选中态与今日态区分：今日始终有标记；选中日有选中样式。今天被选中时两种样式叠加。

### 5.2 日列表

选中某一日后，下方展示该自然日（本地时区 00:00:00～23:59:59）内**当前用户**的全部记录。

| 项 | 规则 |
| --- | --- |
| 排序 | 按记录时间正序（早 → 晚）；同一时间按写入先后（id 升序） |
| 消耗展示 | 绿色 |
| 摄入展示 | 红色 |
| 列表项内容 | 时间（HH:mm）+ 类型文案 + 内容文本；整行可点进详情 |
| 空列表 | 展示「这一天还没有记录」 |
| 改删入口 | 不在列表上直接改删；进入 `/calendar/records/{id}` 后再编辑/删除 |

### 5.2.1 事项详情

路由：`/calendar/records/:id`。刷新必须请求 `GET /api/v1/dailyRecords/{id}`（JWT 隔离；跨用户/缺失 404「记录不存在」）。页面只读展示类型、内容、时间，提供「编辑」「删除」（删除先中文确认）。「返回」回到 `/calendar?date=YYYY-MM-DD`（该记录的上海时区自然日）。

「补记」为次要/文字按钮，带 `date` 进入记录类型选择，不得做成与周切换或首页大按钮同级的大主按钮。

### 5.2.2 月 / 区间列表时间

按月或自定义区间时，列表每一条必须展示上海时区日期+时分（`MM-DD HH:mm`），不得只有内容。日模式展示 `HH:mm`。

类型文案：

- `CONSUME` → 「消耗」
- `INTAKE` → 「摄入」

颜色约定（实现时统一 token）：

| 类型 | 含义 | 颜色 |
| --- | --- | --- |
| 消耗 | 支出型活动 | 绿色 `#16A34A`（可微调，但必须是绿） |
| 摄入 | 摄入型活动 | 红色 `#DC2626`（可微调，但必须是红） |

### 5.3 按筛选导出（xlsx）

入口：日历页，文案「导出」（用户口头仍可叫 csv）。作用于**当前筛选**（单日 / 整月 / 区间）、**当前用户**。

真正 CSV 没有多工作表，因此文件格式为 **xlsx**（Apache POI）。路径仍为 `GET /api/v1/dailyRecords/exportCsv`（历史路径保留）。

当前资料必须同时有身高和体重，否则前端拦截并引导 `/profile/body`，后端返回 HTTP 400「请先填写身高和体重」，不生成文件。

#### 5.3.1 文件

| 项 | 规则 |
| --- | --- |
| 文件名 | 单日 `workout-YYYY-MM-DD.xlsx`；整月 `workout-YYYY-MM.xlsx`；跨日 `workout-from_to.xlsx` |
| MIME | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` |
| 工作表 | Sheet1「事项列表」；Sheet2「成长曲线」 |

#### 5.3.2 事项列表列定义

| 列名 | 说明 | 示例 |
| --- | --- | --- |
| 记录时间 | 上海时区 `yyyy-MM-dd HH:mm:ss` | 2026-08-18 07:30:00 |
| 类型 | 消耗 / 摄入 | 消耗 |
| 内容 | 用户原文 | 跑步 30 分钟 |
| 昵称 | 该条 `recordedAt` 当时有效的资料快照 | 小明 |
| 身高cm | 当时身高；无匹配历史则空 | 175 |
| 体重kg | 当时体重；无匹配历史则空 | 70 |

「当时有效」= 该用户历史中 `changedAt <= recordedAt` 的最后一条快照。禁止用当前资料覆盖更早事项。导出时一次加载该用户历史再内存匹配，禁止按行查库。

行顺序与页面列表一致：时间正序。

#### 5.3.3 成长曲线工作表

| 列名 | 说明 |
| --- | --- |
| 时间 | 历史点 `changedAt`（上海可读时间） |
| 身高cm | 该点身高，单位厘米 |
| 体重kg | 该点体重，单位千克 |

#### 5.3.4 空数据

筛选区间无记录时：仍允许导出（须已填身高体重），事项列表仅含表头，成长曲线仍写出历史点（可为空表头）。

#### 5.3.5 触发

点击后由浏览器下载文件。失败时提示「导出失败，请稍后重试」。未登录则先跳转登录。

### 5.4 成长曲线（在「我的」）

入口：`/profile/body` 表单下方（日历主路径不再放「变化曲线」；`/calendar/trends` 重定向到身体资料页）。

- 单位：身高 cm、体重 kg；X 轴为时间。
- 数据多时可横向拖动（pan）。
- 放大/缩小改变时间粒度：hour / day / week / month，不是 CSS scale。
- 无历史且无记录条数时中文空态。
- 数据来自 `GET /api/v1/profile/trends`。

### 5.5 分享 H5

入口：日历页「分享」，作用于当前筛选。同样须先填身高和体重（前后端闸门与导出一致）。

成功后展示可复制链接：`{WORKOUT_PUBLIC_BASE_URL}/report/{id}`。`id` 为随机 token，不是自增主键。默认基址 `http://localhost:8080`，由配置项 `WORKOUT_PUBLIC_BASE_URL` 覆盖，不要写死局域网 IP。

前端路由：`/report/:id`（React Router 路径参数，比字面 `/report/id=233232` 更自然；语义等同「按 id 打开报告」）。独立页，不走底部三 Tab。

报告内容上下排列：① 用户名称 ② 事项列表 ③ 成长曲线 ④ 建议分析（空态占位，不做真实医疗建议）。展示数据范围 `from`～`to`。

## 6. 我的信息模块

### 6.1 字段

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 昵称 | 字符串 | 否 | 0～32 字；可空 |
| 身高 | 数字 | 否 | 单位 cm；允许 50.0～250.0，一位小数 |
| 体重 | 数字 | 否 | 单位 kg；允许 20.0～300.0，一位小数 |

每个登录用户一份 Profile（按 `userId` 唯一），不是全站单行。

### 6.2 交互

「我的」Tab 先进入二级选项层 `/profile`，**不要**在一页同时展示身高体重、改密、注销。

| 选项 | 路由 | 内容 |
| --- | --- | --- |
| 身体资料 | `/profile/body` | 昵称、身高、体重、资料真实日期（datetime-local，默认此刻）、保存；下方成长曲线 |
| 账号安全 | `/profile/account` | 改密、注销；ADMIN 可见「后台管理」 |
| 退出登录 | 选项层即时执行 | 清 Token，回未登录记录壳 |

1. 点「身体资料」再拉当前用户资料并回填；从未保存过则全空。资料真实日期默认此刻。
2. 用户修改后点「保存资料」。相对上一快照有变化时写入 `work_out_profile_history`（`changedAt` 用用户所选日期时间，缺省服务器 now；同时写入当前资料 `updatedAt`）。
3. 成功提示「保存成功」；失败保留编辑内容。页下方展示成长曲线。
4. 「返回」回到 `/profile` 选项层。
5. 注销须中文确认后再调 `DELETE /api/v1/auth/me`（同时按 userId 批量删除资料历史与分享报告）。

### 6.3 校验

| 条件 | 提示 |
| --- | --- |
| 身高超出范围 | 身高请填写 50～250 之间的数值 |
| 体重超出范围 | 体重请填写 20～300 之间的数值 |
| 非数字 | 请输入有效数字 |
| 保存成功 | 已保存 |

身高、体重均可只填一项。清空后保存表示该字段置空。**导出与分享**要求当前资料身高、体重都已填写。

本期**不计算、不展示 BMI**，不根据数值给出健康建议。

## 7. 数据对象（功能视角）

以下为功能所需最小数据，不是表结构设计终稿。

### 7.1 用户 User

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| username | 唯一用户名 |
| passwordHash | 密码哈希（不明文） |
| createdAt | 注册时间 |

### 7.2 日记录 DailyRecord

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| userId | 所属用户 |
| type | CONSUME / INTAKE |
| content | 文本内容 |
| recordedAt | 用户确认的记录时间 |
| createdAt | 系统创建时间 |
| deleted | 逻辑删除（预留；本期无删除入口则可不暴露） |

### 7.3 个人资料 Profile

## 8. 接口契约（功能级）

与项目整体规范对齐：路径 `/api/v1/...`，路径段 camelCase；POST 业务字段放在 `request` 内；统一响应 `{ code, msg, data }`。  
请求携带 `requestId`、`timestamp`。业务接口需 JWT；鉴权接口公开。

### 8.1 注册

`POST /api/v1/auth/register`

request：`{ username, password }`

data：`{ token, userId, username }`（若注册后直接登录）或仅用户信息（再调登录）。

### 8.2 登录

`POST /api/v1/auth/login`

request：`{ username, password }`

data：`{ token, userId, username }`

### 8.3 新增记录（需登录）

`POST /api/v1/dailyRecords`

request：

| 字段 | 类型 | 必填 |
| --- | --- | --- |
| type | string：`CONSUME` \| `INTAKE` | 是 |
| content | string | 是 |
| recordedAt | string，ISO 8601 | 是 |

`userId` 由服务端从 Token 解析，禁止客户端传入覆盖。

data：新建记录对象（含 id、type、content、recordedAt）。

### 8.4 按日查询记录（需登录）

`GET /api/v1/dailyRecords`

| 字段 | 说明 |
| --- | --- |
| date | `yyyy-MM-dd`，选中日，必填 |

仅返回当前用户数据。`list` 已按 `recordedAt` 正序。

```json
{
  "date": "2026-08-18",
  "list": [
    {
      "id": 1,
      "type": "CONSUME",
      "content": "跑步 30 分钟",
      "recordedAt": "2026-08-18T07:30:00.000+08:00"
    }
  ]
}
```

### 8.5 导出 xlsx（需登录）

`GET /api/v1/dailyRecords/exportCsv?date=yyyy-MM-dd`（亦可 `yearMonth` 或 `from`+`to`，互斥）

返回 xlsx 文件流，`Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`，`Content-Disposition` 带 `.xlsx` 文件名。仅当前用户数据。Sheet「事项列表」表头：`记录时间,类型,内容,昵称,身高cm,体重kg`；Sheet「成长曲线」表头：`时间,身高cm,体重kg`。身体列按该行 `recordedAt` 匹配历史快照。缺身高或体重：HTTP 400「请先填写身高和体重」。

**推荐后端导出**，保证列顺序、中文类型文案、双工作表一致。

### 8.5a 创建分享（需登录）

`POST /api/v1/shareReports`（查询参数与导出相同，互斥）

data：`{ id, url }`。`url` = `{WORKOUT_PUBLIC_BASE_URL}/report/{id}`。缺身高或体重 400「请先填写身高和体重」。无 JWT 401。

### 8.5b 公开报告（无需登录）

`GET /api/v1/reports/{id}`

data：`{ from, to, displayName, records, bodyHistory, advice }`。`advice` 为空占位。未知 token：404「报告不存在」。

### 8.6 查询个人资料（需登录）

`GET /api/v1/profile`

data：`{ nickname, heightCm, weightKg }`，未填字段为 `null`。当前用户一份。

### 8.6a 变化曲线数据（需登录）

`GET /api/v1/profile/trends`

data：`{ bodyHistory: [{ changedAt, nickname, heightCm, weightKg }], recordCounts: [{ date, count }] }`。仅本人；无 Token 401。历史一次查出；条数一次查出 `recordedAt` 再按上海自然日聚合。

### 8.7 保存个人资料（需登录）

`PUT /api/v1/profile`

request：`{ nickname, heightCm, weightKg, changedAt }`，前三项可空；`changedAt` 为资料真实日期（ISO），缺省服务器 now。

data：保存后的完整资料。

### 8.8 错误码

| code / HTTP | 场景 |
| --- | --- |
| 200 | 成功 |
| 400 | 参数校验失败；缺身高体重导出/分享「请先填写身高和体重」 |
| 401 | 未登录、Token 无效或过期 |
| 404 | 记录不存在；报告不存在 |
| 500 | 服务异常 |

业务校验失败用 HTTP 400 + `msg` 中文即可，暂不扩展领域码。

## 9. 启动方式（功能要求）

前后端不分离：

1. React 构建产物由 Spring Boot 静态资源托管。
2. 用户在项目根目录通过 CLI 启动（如 `./mvnw spring-boot:run` 或文档给出的一条命令）。
3. 启动成功后访问约定地址（如 `http://localhost:8080`）即可看到导航壳，并完成注册登录与三个业务页。
4. 依赖 MySQL：启动说明中写明库名、字符集 utf8mb4、以及最小 DDL（含 `user`、`daily_record.user_id`、`profile.user_id`）。

具体命令在工程 README 中维护；本功能文档要求「一条命令可启动、浏览器可完成登录与记账闭环」。

## 10. 异常与边界

| 场景 | 期望 |
| --- | --- |
| MySQL 不可用 | 启动失败或接口 500，页面提示服务异常，不出现无说明白屏 |
| Token 过期 / 伪造 | 401，前端清 Token 并跳转登录 |
| 跨用户访问 | 查询 / 导出 / 资料只返回当前 userId 数据，不泄露他人 |
| 跨日记录 | 记到哪一天，就只出现在那一天的列表与导出中 |
| 时区 | 以运行环境本地时区划分自然日；服务端与前端约定同一时区（默认 `Asia/Shanghai`） |
| 超长内容 | 前端限制 + 后端校验，以后端为准 |
| 连续保存 | 每次保存一条独立记录，后一次不覆盖前一次 |
| 刷新页面 | 已保存记录仍在；Token 仍在则保持登录；未保存输入可丢失 |
